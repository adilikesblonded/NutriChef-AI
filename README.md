# NutriChef AI

> An AI-powered ingredient recognition and nutrition analysis system that detects grocery items from images using a custom-trained YOLOv8 object detection model and provides nutritional information through a backend API.

---

# Overview

NutriChef AI is a computer vision project that recognizes raw ingredients and common grocery products
and provides complete recipes suited to your nutritional goals that utilize the ingredients you presented.

The project combines multiple object detection datasets found on the internet, performs  preprocessing and label remapping, trains a custom YOLOv8 model, and integrates the detection pipeline with spoonacular APIs to provide nutritional data and recipes.

This project emphasizes real world grocery recognition, making it suitable for applications such as smart kitchens, dietary tracking, and meal planning.

---

* Custom YOLOv8 object detection model fine-tuned on a

# Dataset

Current sources include:

* LVIS Fruits & Vegetables
* GroZi Grocery Dataset (filtered and normalized)

Significant preprocessing has been performed to improve dataset quality:

* Normalized class names across datasets
* Remapped annotation IDs
* Removed irrelevant grocery categories
* Merged overlapping food categories
* Generated a unified YOLO-compatible dataset
* Analyzed class distributions for dataset refinement

The dataset currently contains approximately:

* 70 object classes
* Thousands of annotated object instances

---

# Training Pipeline

Current workflow:

1. Collect datasets
2. Normalize class names
3. Merge compatible categories
4. Remap annotation labels
5. Generate YOLO dataset structure
6. Create training configuration
7. Train YOLOv8 model
8. Evaluate performance
9. Analyze errors
10. Refine dataset
11. Retrain

## Folder Breakdown

### `analysis/`

Contains exploratory data analysis (EDA), dataset statistics, class distribution analysis, and visualizations used to evaluate dataset quality before and after preprocessing.

---

### `datasets/`

Stores the original raw datasets collected from multiple public sources before any preprocessing or label modifications. These datasets are used as the starting point for building the unified training dataset.

---

### `iterations/`

Maintains records of each major training iteration, including model performance metrics, experiment notes, training curves, and evaluation results. This folder documents the evolution of the project and enables comparison between successive model improvements.

---

### `metadata/`

Contains metadata files required during dataset preprocessing, including class mappings, label remapping information, normalization tables, and other configuration files used to unify multiple datasets.

---

### `remapped_datasets/`

Stores the processed datasets after class normalization, annotation remapping, and dataset merging. These datasets are converted into a consistent YOLO-compatible format before training.

---

### `runs/`

Automatically generated by Ultralytics during training.

Contains:

- Training logs
- Model checkpoints (`best.pt`, `last.pt`)
- Loss curves
- Precision-Recall curves
- Confusion matrices
- Validation outputs

This folder is primarily used for experimentation and is generally excluded from version control.

---

### `scripts/`

Contains the project's Python scripts responsible for dataset preprocessing, annotation remapping, dataset merging, analysis, training automation, and other utility functions.

Examples include:

- Dataset merging
- Label remapping
- Class normalization
- Dataset inspection
- Training scripts

---

### `training/`

Contains training configurations, experiment settings, and supporting files used during model training. This folder centralizes the resources required to reproduce training runs and manage future experiments.
